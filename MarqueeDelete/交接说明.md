## 一、这个包是什么

《城市：天际线 II》代码模组 **Marquee Delete（框选批量删除）** 的完整工程快照，用于在新对话中继续开发。

包内已剔除两类体积大且可重建的内容：
- `ui/node_modules/`（约 118 MB，用 `npm install` 恢复）
- `dist/`、`publish/`、`tests/bin`、`tests/obj` 等可再生成的构建产物（保留在 `logs-and-build-artifacts/` 中的仅限 DLL 与构建校验结果）

## 四、关键事实（新对话请先读）

- 游戏 **Cities: Skylines II 1.6.4f1**（1097.158a）；`Game.dll` MVID `46198354D4F94D23BF327E3C085D8B92`，SHA256 `F076DF4B70AA0F21A80345E03A052CA2273BC6754F41DAB7E63D837837A43745`。模组启动时校验 MVID，不符会自动停用。
- 删除通过 `ToolOutputBarrier` 提交：先移除 `Applied/Created/Updated`，再加 `Deleted`；附属车道、子网络等交给游戏原生 `PostTool` / Modification 阶段清理。
- 撤回使用 `CreationDefinition` + `ObjectDefinition`/`NetCourse` 的 **Permanent** 载体（`Updated` + `Deleted`），按类型分批、按帧耗时自适应降速；父实体通过 `PrefabRef` + `Game.Objects.Transform` 匹配真实实体，绝不提交 `Entity.Null` 父对象。
- 撤回上限：最多 5 个快照、每个 8000 条记录；仅恢复几何与部分属性，**不恢复住户、经济或完整模拟状态**，车辆/市民不支持撤回。
- 撤回期间（含暂停）禁止新的框选删除。
- 所有离线验证可通过 `tests/run_tests.ps1` 复现；`inGameTested` 仍为 `false`，游戏内稳定性未由自动化验证。

## 五、如何恢复开发环境

```powershell
cd MarqueeDelete
cd ui
npm install                       # 恢复 node_modules
$env:CSII_USERDATAPATH = "<仓库>\dist\_ui_stage"
npm run build                     # 生成 MarqueeDelete.mjs / .css / images/
cd ..
pwsh -File .\build.ps1            # 编译 C#，输出 dist/MarqueeDelete.dll
pwsh -File .\tests\run_tests.ps1  # 单元 + 删除回归
pwsh -File .\tests\verify_cecil.ps1
pwsh -File .\install.ps1          # 安装到本地游戏
```

注意：
- 必须使用 **pwsh（PowerShell 7+）**；Windows PowerShell 5.1 会导致 Cecil 加载失败。
- `build.ps1` 依赖本机 Roslyn 路径与游戏 Managed 目录（`D:\steam\steamapps\common\Cities Skylines II\Cities2_Data\Managed`），换机器需修改。
- `install.ps1` 只会写入带 `.marqueedelete-owned` 标记的目录，不会覆盖他人模组。

## 六、发布

```powershell
pwsh -File .\publish.ps1 -Mode Publish      # 首次（会返回 ModId，需回填 XML）
pwsh -File .\publish.ps1 -Mode NewVersion   # 发新版本（当前用法）
pwsh -File .\publish.ps1 -Mode Update       # 仅更新页面元数据
```

`PublishConfiguration.xml` 必须包含 7 个字段：`DisplayName`、`ShortDescription`、`LongDescription`、`Thumbnail`、`ModVersion`、`GameVersion`、`Tag`。发布器复用游戏内 Paradox 登录，无需在脚本里存密码。

## 七、当前已知边界

- 撤回的“进度”表示**已提交请求数**，不是游戏已完成重建数；日志末尾会明确写出 `game application is not verified`。
- 复杂建筑（服务建筑、升级件、子区域/子路网多）的恢复仍可能单帧偏重。
- 大选区删除在高负载、多模组环境下仍有卡死/闪退风险，发布说明中已提示分批操作。
- 反馈问题请附带 `MarqueeDelete.status.log`、`Player.log`、游戏版本、模组列表与操作步骤。
