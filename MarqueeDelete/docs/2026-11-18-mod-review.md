# 批量删除模组代码审查与修复建议

审查基线为 GitHub `main` 的 `d9c8097`，模组版本为 2.7.7。本分支为 2.7.8，新增了红绿灯与过街斑马线的独立移除。检查结合本机游戏 1.6.4f1 的托管程序集、模组源码、离线测试和界面渲染。涉及存档、交通模拟和原版界面交互的验收项目列在文末。

## 优先处理顺序

| 优先级 | 问题 | 先做什么 |
|---|---|---|
| 高 | 撤回进度记录的是创建请求，玩家仍可能遇到少恢复、连接未恢复 | 对照游戏生成的对象确认结果，保留未完成的记录 |
| 高 | 超大附属组会在单批中提交，删除超时后仍可能有命令继续执行 | 单独确认超大组，记录已提交与待复核目标 |
| 高 | 路口设置变化暂未纳入撤回，其他交通模组可能同时修改路口 | 按位记录改动和回放条件，增加保存重载与冲突测试 |
| 中 | 大选区的空间搜索和最终级联分析仍可能占用主线程 | 先采样定位长帧，再把预览做成可取消的小批工作 |
| 中 | 更新兼容判断依赖单个游戏构建指纹，界面挂载缺少运行反馈 | 分开验证道路写入、撤回和面板，记录可用功能 |
| 中 | 确认和取消同时由游戏输入和浏览器监听，部分文档落后于操作 | 统一确认入口，补齐窄面板和按键回归测试 |
| 中 | GitHub 检出后需要手动改本机路径才能构建 | 参数化游戏目录和编译器路径，给纯逻辑测试接持续集成 |

## 1. 撤回需要确认游戏确实创建了目标

`DeletionUndoManager.Step` 在发出有效的创建请求后增加 `RestoredCount`。有些建筑的附属物会等父实体出现，有些网络会因端点或车道证据不足而跳过。道路请求通过后，原版仍需重建车道和连接。撤回历史在开始时交给活动操作，停止时会释放剩余枚举器。遇到一项失败或只恢复一种资产后，剩余对象缺少逐项复核入口。现有界面已经使用「已提交」描述部分结果，应继续沿用这个准确的表述。[撤回提交与停止](../DeletionUndo.cs) · [撤回快照状态](../SelectiveUndoLogic.cs)

建议给建筑、道路和地表建立提交后的检查。建筑用预制件、位置、朝向和可确认的所有者匹配；道路再核对两端及可行驶车道。进度分别显示待提交、已提交、已确认及跳过。完成后保留超时或证据不足的记录，玩家可查看跳过原因。只勾一类时保留未选类别的快照，避免一次操作消耗整份记录。

验收用例选一段连接现有路口的道路、一栋带附属建筑的建筑、一个地表区域。分别撤回，检查实际实体与连接，暂停后继续，停止后检查未提交项。测试覆盖道路位置已被占用、父建筑迟到、同一位置出现两个候选三种情况。

## 2. 大批删除需要明确哪些已经发生

批量拆除按上一批用时调整数量，并观察已提交实体是否消失。超大设施会独占一批，但一个设施及其附属物仍可能超过普通批次预算。普通批次与节点清理分别有 3 秒与 6 秒的观察窗口。单次小批的日志还用整个模拟世界的实体数变化做近似值，人口、车辆和原版更新也会影响它。界面现有的「复核剩余」可以继续使用，应把单批和多批的状态口径统一。[拆除排程和超时](../MarqueeDeleteToolSystem.cs) · [附属关系与路口保护](../Cascade.cs)

建议在确认前单列最大的设施组和可提交目标数。达到重负载阈值时，用户可以先处理普通组，也可以单独确认超大组。把观察从固定的墙钟秒数改为游戏可推进的更新次数加超时上限，暂停游戏期间显示等待。记录每批的实际目标集合，超时后继续观察已经提交的一组，让「未提交」和「已提交尚未观察到」各自可见。

验收分别覆盖超大服务建筑、跨越多个路口的道路链和暂停模拟时提交。拆除结束时，已确认、保留与待复核的集合要能对应最初确认的目标。重试只能从最新复核生成新计划。

## 3. 大城市拖框要减少主线程等待

`SelectionCollector.Collect` 会在启用相关类别时读取静态、移动、管网、地表空间树，各自等待依赖完成。现有预览会根据耗时降低刷新频率，但每次刷新仍执行一次完整采集，松鼠标后的级联分析也在主线程完成。曲线相交用固定步数近似，细窄选区碰到高曲率道路时值得用专项用例核对。[搜索与曲线相交](../Selection.cs) · [拖框刷新间隔](../MarqueeDeleteToolSystem.cs)

建议先把搜索等待、候选筛选、级联分析、铺设高亮这四段分别计时。用同一存档连续框选小街区、密集商业区和跨河管网，记录拖动及松手时的第 95 百分位和最大耗时。第一步复用结果容器，延后隐含对象统计到确认前，跳过当前筛选用不到的空间树。若等待仍占主要耗时，把读取独立数据快照和后续计算拆开，以选区修订号舍弃旧结果。跨线程部分只读已取得安全依赖的数据。

## 4. 版本更新要分别验证每种写入

兼容层已经区分搜索、拆除、撤回和 UI，并在未知游戏构建时保留部分预览。拆除、撤回及这次的路口设施改动都受已验证构建约束。Cecil 符号能解析说明找得到接口。网络重算时机、实体上出现的组件和原版界面的挂载位置仍要跟游戏一起验证。前端依赖原版工具面板的模块路径，找不到时会跳过注入，当前缺少一条明确的面板挂载结果。[游戏版本判断](../Compatibility.cs) · [面板挂载](../ui/src/index.tsx)

建议让界面在成功挂载时向 C# 回报模块版本和可用控件。保持未知构建只预览的策略，把拆除、撤回和修改路口的探测项目独立列在兼容日志。每次游戏升级后先编译和跑符号检查，再用同一个小测试城市验证选区、删除确认、撤回与保存重载。每项通过后记录游戏版本和构建指纹。

## 5. 确认窗口、快捷键与说明

普通确认和重要建筑二次确认在浏览器监听 Enter、Esc，游戏侧同一时间也能读到键盘事件和自定义操作。2.7.7 已过滤浏览器按键连发，也让重要建筑弹窗优先；浏览器与游戏状态更新跨帧时仍应验证一次按键只触发一个阶段。旧使用说明还把锁定选区后的右键写成清空，当前的行为是右键移除单个、Esc 清空。[界面按键处理](../ui/src/mods/bulldoze-marquee-section.tsx) · [游戏输入处理](../MarqueeDeleteToolSystem.cs) · [旧使用说明](../使用说明.md)

建议把键盘确认统一到游戏工具状态，界面按钮继续提交同一动作。以选择版本和输入帧标记确认，只允许每份已显示的选择处理一次按键。验证长按 Enter、有重要建筑时连续按两次、配色窗口持有焦点、重新绑键、开着 Anarchy、中文和英文高缩放。更新操作说明，并让「待确认」「正在提交」「需复核」各有清楚的状态和按钮。

## 6. 构建和测试应能从全新检出开始

`build.ps1` 的游戏程序集和 Roslyn 编译器路径来自开发机。离线测试脚本使用 `--no-restore`，第一次检出必须先还原项目依赖。当前离线测试可覆盖筛选、几何、级联与提交策略，真实 Unity ECS 播放及游戏内面板仍需独立检查。[构建脚本](../build.ps1) · [测试脚本](../tests/run_tests.ps1) · [离线回归范围](../tests/DeletionRegression.cs)

建议给构建脚本增加游戏安装目录和编译器参数，沿用本机默认配置。GitHub CI 可以跑 .NET 纯逻辑、TypeScript 和中英文键检查；本机再跑依赖游戏 DLL 的 Cecil 校验。把两种验证结果分别保存，GitHub 仓库只跟踪源码和素材。

## 本分支的路口设施与实机验收

本分支通过 2,826 项逻辑检查、201 项离线拆除回归与 80 项中英文界面检查。Cecil 对本机 1.6.4f1 解析了 882 个成员引用和 327 个类型引用，缺失为 0。界面检查使用打包后的脚本与样式，以及模拟的游戏数据。Webpack 仍有既有的 Sass 旧 API 弃用提示。

地面视图打开批量删除，再展开 **管网细分**，进入 **路口设施**。红绿灯选项按路口中心匹配，过街斑马线按道路端点匹配。移除走原版道路升级标记，确认时重新核对目标，提交时再检查同一对象、端点与方向。按每帧最多 12 个目标实体提交，计数表示提交请求。铁道路口、活动桥信号、转盘、隧道、外部连接和受保护的固定网络会跳过。路中共用过街点和中央隔离带开口仍用原版道路服务处理。有信号灯的普通路口至少要接入三段可合并的双向道路，才允许移除斑马线，避免原版随过街设施重算时关掉信号灯。[设施选取和路网写入](../RoadFacilities.cs)

路口设置暂时用原版道路服务恢复。后续可加入专门的可撤回记录，只保存改动过的标记位及预制件、端点和版本。撤回时对照现有状态，避免覆盖玩家或其他交通模组后来作出的转向、让行或信号设置。

| 测试场景 | 完成标准 |
|---|---|
| 分别移除普通十字路口的红绿灯与斑马线 | 每次只改变选中类别，交通仍能经过路口 |
| 同一长路段两端都有斑马线 | 框住一端，只移除那一处；覆盖左右行交通和反向铺路 |
| 保存后重载 | 设施设置仍在，车道和行人路径正确重算 |
| 关闭通用确认、画大选区、按住 Enter | 设施仍先锁定并确认一次，分批时 Esc 可停止未提交目标 |
| 已关闭的设施以及受保护路口 | 无额外移除请求，原版设施和道路保持可用 |
| 路中共用斑马线、中央隔离带开口及有单行道路口 | 核对普通路口可编辑的边界，避免联动移除邻侧斑马线或信号灯 |
| 启用其他交通模组 | 检查自定义信号相位、转向限制、优先级及人行路径是否保留 |

实机验收可使用单独的测试存档。优先验证表中的前四项，再决定是否扩大可编辑路口范围或发布到模组平台。
